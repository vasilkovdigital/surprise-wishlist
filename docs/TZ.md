Версия 7 · документ для разработчика. Описывает целевой продукт и отмечает, что уже сделано в прототипе.
Прототип: https://vasilkovdigital.github.io/surprise-wishlist/ · код: https://github.com/vasilkovdigital/surprise-wishlist

Обозначения: ✅ реализовано в прототипе · 🔜 запланировано (в прототипе нет или заглушка).

---

## 1. Цель и ценность

Маркетинговый веб-апп Surprise.by для тех, кто хочет что-то попробовать, но сам себе не покупает. Человек свайпает впечатления как в Tinder: нравится — в вишлист, нет — дальше. Вишлистом и отдельным впечатлением можно поделиться с друзьями и гостями на день рождения. Переход на сайт идёт по UTM-ссылке; за заказ через приложение даётся бонус.

**Преимущества:** простота, актуальность (каталог синхронизируется с сайтом ежедневно), удобный шеринг, бонус за заказ из приложения.

**Две критичные для компании вещи:**
1. **Данные человека для CRM-поздравлений с ДР:** почта, имя, дата рождения — база; плюс необязательные пол, возраст, должность, интересы (§6).
2. **Распространение:** человек делится ссылкой на свой вишлист или на отдельное впечатление (§9).

## 3. Пользовательские сценарии

1. **Первый запуск ✅.** Онбординга нет: приложение сразу открывается на вкладке «Впечатления».
   - **О приложении ✅.** Кнопка «О приложении» в хедере открывает окно: слоган «Выбирай. Делись. Пробуй.», три шага (выбирайте / делитесь / пробуйте), бонус, **подписка на Telegram-канал** (карточка «Новинки и подборки в Telegram», кнопка «Подписаться» → https://t.me/mysurpriseby, в новой вкладке; ссылка без UTM, событие `outbound_click` с `campaign: about_telegram`), **частые вопросы** (регистрация, кому виден вишлист, как поделиться, бонус, пропущенные карточки, удаление данных), блок «Ваши данные», ссылка на surprise.by (с UTM) и размер/дата каталога. Событие `about_open`.
2. **Свайп ✅.** Вправо / ♥ — в вишлист; влево / ✕ — пропуск; тап по карточке — подробности; «Вернуть» отменяет последний свайп; стрелки ←/→ на десктопе.
3. **Анкета после 10-го свайпа ✅.** Один раз предлагается модальное окно «Расскажите о себе» (имя, день и месяц рождения, год по желанию, чекбокс согласия). Можно «Позже» — повторно окно не показывается, анкета остаётся доступной на экране профиля (значок в шапке).
4. **Поиск ✅.** Иконка лупы в хедере открывает окно поиска: поле с автофокусом, результаты (до 40) со списком «фото · название · цена», тап открывает карточку. Поиск по названию и описанию, без учёта регистра и «ё/е», все слова запроса должны встретиться; совпадения в названии выше. Не зависит от активных фильтров. События `search_open`, `search` (`q`, `results`).
5. **Фильтры ✅.** Над лентой два ряда: 1) кнопка «Фильтры» (**зелёная**, при активных фильтрах чёрная со счётчиком), «ИИ-подбор» (**сиреневая**, неактивная, с плашкой «Скоро»), категории (активная — голубая); 2) **«Повод»**: День рождения, Новый год, 14 февраля, 23 февраля, 8 марта, Свадьба (праздники упорядочены по ближайшей дате, «круглогодичные» — по краям). Ряд «Повод» — быстрый доступ к тому же фильтру `occasion`, что и в полном окне. Кнопка «Фильтры» (со счётчиком активных) открывает полное окно (§5).
6. **Карточка ✅.** Галерея, видео, описание, цена, «В вишлист», «Смотреть на surprise.by» (UTM), «Поделиться этим впечатлением».
7. **Вишлист ✅.** Сетка, итоговая сумма, удаление, «Поделиться вишлистом», напоминание о ДР.
8. **Профиль ✅.** Анкета (или её редактирование), настройки, просмотр хранимых данных, удаление данных.
9. **Чужая ссылка ✅.** Открывается без анкеты; кнопка «Собрать свой вишлист» ведёт на вкладку «Впечатления».

Навигация: нижняя панель состоит **только из двух вкладок**: «**Впечатления**» и «Вишлист» (со счётчиком). **Шапка (хедер) ✅:** логотип, поиск (лупа), ссылка «О приложении» и **значок профиля** справа — круглый аватар с инициалом имени в цвете бренда; пока анкеты нет, показан силуэт с розовой точкой-подсказкой. Под шапкой — тонкая «конфетти-полоса» из четырёх цветов бренда (голубой, зелёный, розовый, сиреневый). Когда открыт профиль, ни одна нижняя вкладка не подсвечена, а у значка профиля розовое кольцо.

**Терминология:** в интерфейсе вкладка называется «Впечатления» (раньше «Колода»); слово «колода» в этом документе и в коде (`Deck`, `buildDeck`) — технический термин для стопки карточек и пользователю не показывается.

## 4. Каталог (данные)

**Источник:** `https://surprise.by/google_merchant.csv`, обновляется на сайте ежедневно. Формат: разделитель `|`, UTF-8, значения в кавычках, первая строка — заголовок. Поля: `id | title | description | product_type | link | image_link | additional_image_link | video_link | price | availability | custom_label_0 | custom_label_1 | custom_label_3`. На момент написания 355 позиций, все `in_stock`.

**Особенности данных:**
- Цена строкой `"105 BYN"`: парсится в число, валюта всегда BYN (14–1900, медиана 150).
- Главное фото есть у всех; галерея — `additional_image_link` через запятую (у 347); видео YouTube — у 46.
- `product_type` — одна строка с десятками тегов (получатели, поводы, категории), много шума.
- `description` ~440 символов, возможны повторяющиеся точки.
- Ссылки `link` без параметров: UTM добавляем сами.

**Нормализация ✅** (`scripts/sync.ts`, справочник `scripts/taxonomy.ts`) → `public/data/products.json` и `meta.json`:

```
Product { id, title, description, url, image, imageLocal?, images[], video?, priceByn,
          audience[], occasions[], categories[], interests[], cities[], ageGroups[],
          priceBucket, isGiftCard }
```

Справочники значений (`src/lib/config.ts`):
- **Категории** (тип впечатления): `active` Активный отдых, `spa` СПА и красота, `master` Мастер-класс, `food` Бары и рестораны, `quest` Квесты, `photo` Фотосессия, `fly` Полёты, `creative` Креатив, `company` Для компании.
- **Интересы** (один набор в профиле и в фильтре): `spa` SPA и красота, `food` Гастрономия, `extreme` Экстрим, `creative` Творчество, `sport` Спорт, `romance` Романтика.
- **Города:** `minsk`, `brest`, `grodno`, `gomel`, `vitebsk`, `mogilev`.
- **Возраст получателя:** `child` до 12, `teen` 13–17, `adult` 18–44, `senior` 45+.
- **Поводы:** `bday`, `mar8`, `feb14`, `feb23`, `ny`, `wedding`.

**⚠ В фиде нет отдельных полей «город», «возраст», «пол», «интересы».** Сейчас они **выводятся эвристикой** из тегов `product_type` и текста названия/описания (правила — `INTEREST_RULES`, `CITY_RULES`, `deriveAgeGroups` в `scripts/taxonomy.ts`). Фактическое покрытие на выгрузке из 355 позиций:

| Признак | Покрытие | Следствие для фильтра |
|---|---|---|
| Интересы | 320 из 355 | работает, но по ключевым словам — возможны неточности |
| Город | только 33 из 355 (Минск 28, Брест 5, Гродно 1) | у остальных город неизвестен: **такие позиции показываются при любом выбранном городе** |
| Возраст получателя | по тегам «Детям», «Родителям», «Отдых для всей семьи» и словам «детский…»; остальные считаются «18–44» | для «13–17» и «45+» результат приблизительный |
| Пол | по тегам «Женщинам/Девушкам/Жене/Сестре» и «Мужчинам/Парням/Мужу/Брату»; позиции без таких тегов нейтральны и показываются в обоих вариантах | |
| Повод | по тегам «Подарки на …» | строгий фильтр |

**Требование к разработке:** договориться с командой сайта о добавлении в фид явных полей (`city`, `age_group`, `gender`, `interests`) и перейти на них; эвристику оставить как запасной вариант.

Подарочные карты и наборы (`isGiftCard`) показываются в конце колоды.

**Синхронизация ✅:** `npm run sync` (флаг `--with-images` скачивает фото в `public/img/` для полного офлайна). При ошибке сети остаётся предыдущий снимок; без снимка сборка падает. В CI запускается при каждой сборке. Валидация: уникальный `id`, наличие `link`, `image_link`, цены > 0; меньше 20 позиций — ошибка. В футере вишлиста — дата обновления каталога. При загрузке клиент подставляет значения по умолчанию для новых полей, если в кэше остался старый снимок.

🔜 **Новые впечатления:** при синхронизации сравнивать множество `id` с предыдущим снимком, помечать новые (`firstSeenAt`, `isNew`). Нужно для пуш-уведомлений (§10) и бейджа «Новое».

## 5. Колода, фильтры, ИИ-подбор

**Порядок колоды ✅** (`src/lib/deck.ts`, покрыт проверкой):
1. Лайкнутые не показываются никогда.
2. Ещё не виденные — перемешаны стабильно (seed хранится в `wl.seed`, порядок не меняется после перезагрузки); подарочные карты и наборы — в конце.
3. **Пропущенные (✕) переносятся в конец колоды**, в порядке пропуска (самые давние раньше). Это поведение по умолчанию.
4. **Настройка «Возвращать пропущенные»** (профиль → «Настройки», по умолчанию включена). Если выключить, пропущенные больше не показываются; на экране «Вы всё посмотрели» появляется кнопка «Показать пропущенные снова». Настройка хранится отдельно от анкеты (`wl.settings`) и доступна без заполнения анкеты.
5. Когда колода пуста: текст зависит от настройки; ведёт в вишлист.

**Фильтры ✅.** Два уровня:
1. **Быстрый ряд над колодой:** чипсы категорий («Все» + категории, у которых есть позиции) — одно касание.
2. **Кнопка «Фильтры» (со счётчиком активных)** открывает окно со всеми параметрами:

| Параметр | Выбор | Логика |
|---|---|---|
| Город | один из 6 | позиции с известным городом — только выбранный; **без города — показываются всегда** (см. §4) |
| Категория | одна | совпадает с быстрым рядом (общее состояние) |
| Интересы | несколько | пересечение (хотя бы один) |
| Цена, BYN | «от» и «до» + пресеты «до 50», «50–100», «100–300», «от 300» | включительно |
| Возраст получателя | один из 4 | по `ageGroups` |
| Пол получателя | «Для неё» / «Для него» | подходящие по тегам + нейтральные |
| Повод | один из 6 | строгое совпадение |

Окно показывает живой счётчик «Показать (N)»; при N = 0 кнопка неактивна. «Сбросить» очищает всё. Состояние хранится в `wl.filters`; при загрузке старых сохранений недостающие поля заполняются значениями по умолчанию.
**Принцип:** эти фильтры предназначены для тех, кто **выбирает подарок другому** (параметры — получателя). Анкета профиля (§6), наоборот, описывает самого пользователя как получателя подарков, поэтому поле «Кому дарите» в неё не входит. 🔜 Возможное развитие: предзаполнять фильтры из профиля (интересы, город) для персональной колоды.

**ИИ-подбор 🔜.** В ряду фильтров первой стоит неактивная кнопка «✨ ИИ-подбор» с плашкой «Скоро» (`disabled`, `aria-disabled`). Ожидаемое поведение будущей функции: человек описывает получателя/повод свободным текстом, сервис возвращает ранжированную подборку каталога. Требует бэкенда и LLM-интеграции; контракт будет определён отдельно.

## 6. Профиль и анкета

**Когда запрашивается ✅:** не при входе, а предложением после **10-го свайпа** (лайк и пропуск считаются вместе), один раз (`wl.profileAsked`). Всегда доступна на экране профиля (значок в шапке). В окне после 10-го свайпа — только базовые поля (имя, день и месяц рождения, год по желанию, согласие); остальное — на самом экране профиля.

**Состав анкеты** — по таблице «4.2 Профиль клиента» (заказчик). Строка «Кому дарите» намеренно **не включена**: анкета для тех, кому дарят; для дарящих есть фильтры (§5).

| Поле | Зачем | Обязательность | Валидация / примечание |
|---|---|---|---|
| Имя | обращение в письмах | обязательно | 2–40 символов |
| Дата рождения | поздравление, подарок от нас, вишлист | **день и месяц** обязательны, **год необязателен** | три списка «день / месяц / год»; проверка существования даты (в т.ч. 29 февраля без года); без года возраст не считаем |
| Телефон | Viber и SMS | по желанию | нормализуется (`+375…`), 9–15 цифр; **отдельный чекбокс согласия** на Viber/SMS появляется при вводе номера |
| Пол | подборки и обращение | по желанию | `f` / `m` / `o` |
| Возраст | подборки по возрасту | **не вводится, считается** | только если указан год рождения |
| Интересы | основа персонализации | по желанию, несколько | SPA и красота, Гастрономия, Экстрим, Творчество, Спорт, Романтика |
| Город | география предложений | по желанию | Минск, Брест, Гродно, Гомель, Витебск, Могилёв, «Другой город» |
| Сфера деятельности | B2B и корпоративные предложения | по желанию | свободный текст до 60 символов |
| Почта | рассылки, поздравления | по желанию (обязательна при регистрации) | формат e-mail |
| Согласие на рассылки | поздравления и подборки | чекбокс, по умолчанию выключен | |

Колонка «Где хранить / источник» в таблице заказчика на скриншоте обрезана — уточнить.

**Модель** (`localStorage: wl.profile`, версия схемы `v:2`, `src/lib/profile.ts`):

```
Profile { v:2, name, birthDay, birthMonth, birthYear?, phone?, phoneConsent,
          email?, gender?, city?, industry?, interests[], marketingConsent,
          createdAt, updatedAt }
```
**Миграция:** профиль `v:1` (`birthDate`, `position`, интересы-категории) приводится к `v:2` при загрузке: `position` → `industry`, категории → интересы.

**Экран профиля ✅** (открывается значком-аватаром в шапке; повторное нажатие на значок или любая нижняя вкладка возвращают назад): аватар-инициал в цветах бренда, возраст, форма, блок «Какие данные хранятся» (JSON, который уйдёт в БД), «Удалить мои данные» (удаляет всё локальное). Если анкеты нет — форма создания и настройки. За 30 дней до ДР — подсказка отправить вишлист гостям (в профиле и вишлисте).

**Миграция при регистрации 🔜:** объект `wl.profile` → профиль в БД 1:1; имя и дата подтягиваются автоматически, пароль и подтверждение почты добавляются в форме регистрации. Вишлист (`wl.liked`) переносится в аккаунт.

## 8. Регистрация (🔜, учтено в архитектуре)

Триггер: когда в вишлисте **более 3** впечатлений. Поля: почта, пароль, дата рождения (имя и остальное — из профиля).
В прототипе: флаг `FEATURE_REG_GATE` и порог `REG_GATE_AFTER` в `src/lib/config.ts`; при `true` показывается заглушка. Данные вишлиста и профиля сразу изолированы в `src/state.ts`, чтобы заменить `localStorage` на репозиторий с серверным хранением.

## 9. Шеринг

Два объекта шеринга, ссылки работают без регистрации и без бэкенда (весь список внутри URL):

| Что | Формат ссылки | Что видит получатель |
|---|---|---|
| Вишлист ✅ | `#/w/1~<код>?n=<имя>&u=<id отправителя>` | «Вишлист: Имя», карточки только для чтения |
| Одно впечатление ✅ | `#/i/<id>?n=<имя>&u=<id отправителя>` | «Имя делится впечатлением», кнопка «Посмотреть» |

- Код вишлиста: отсортированные ID, дельта-кодирование, base36 через точку; префикс `1~` — версия формата.
- Параметр `u` — анонимный id отправителя (см. §12): по нему считаются рефералы; получатель передаёт его дальше в `ref` исходящих ссылок.
- Имя отправителя подставляется из профиля **автоматически**, без поля ввода (если анкеты нет — ссылка без имени).
- Если ID нет в текущем каталоге: «Впечатление больше недоступно», остальной список не ломается.
- **Окно «Поделиться» ✅:** только ссылка (поле для чтения) и иконки: **копировать**, **Telegram**, **WhatsApp**, **Viber**, **Instagram**; на устройствах с системным шерингом — ещё «Другие приложения». Поля ввода текста нет.
  - Telegram / WhatsApp / Viber открываются через deep-link с готовым текстом и ссылкой.
  - **Instagram:** веб-ссылки для отправки у Instagram нет; кнопка копирует ссылку и открывает Direct с подсказкой «вставьте её в чат».
- Кнопки вишлиста «Поделиться вишлистом» — во вкладке «Вишлист»; «Поделиться этим впечатлением» — в карточке.
- События аналитики `share` содержат `kind` (list/item) и `via`.
- 🔜 Короткие ссылки вида `/w/abc123` и серверные OG-превью (картинка вишлиста в соцсетях) — требуют бэкенда.

## 10. Пуш-уведомления о новых впечатлениях (🔜)

**Цель:** возвращать пользователей, сообщая о новых впечатлениях в каталоге.

- **Технология:** Web Push (PWA, Push API + service worker, VAPID-ключи). Уже есть `public/sw.js` и манифест.
- **Триггер:** ежедневная синхронизация каталога обнаруживает новые `id` (§4); сервер формирует рассылку.
- **Сегментация (по возможности):** по `interests[]` профиля и по категориям, которые человек чаще лайкает; без профиля — общая рассылка.
- **Согласие:** подписка только по явному действию — переключатель в профиле (сейчас неактивный, «Скоро») и/или предложение после первого лайка. Нативный запрос разрешения браузера не показывать при загрузке.
- **Ограничения:** не чаще 1 уведомления в день (и не чаще 2–3 в неделю по умолчанию), тихие часы, объединение нескольких новинок в одно уведомление, отписка одним нажатием.
- **Содержимое:** заголовок «Новое в Surprise», название и фото, по тапу — открывается карточка нового впечатления (`#/i/<id>`) с UTM `utm_medium=push`.
- **Платформы:** iOS (Safari 16.4+) поддерживает Web Push только для приложения, добавленного на экран «Домой» — нужен показ инструкции «Установить»; Android/десктоп работают в браузере.
- **Бэкенд:** хранилище подписок (endpoint, ключи, id устройства/пользователя, согласие, время подписки), отправка (серверный cron после синка), обработка недействительных подписок.
- **Метрики:** подписки, доставлено, открыто, отписки.

## 11. CRM и поздравления с ДР (🔜)

Источник данных: профиль (`name`, `birthDay`/`birthMonth`/`birthYear?`, `email`, `phone`, `gender`, `city`, `industry`, `interests`) и согласия: `marketingConsent` (email) и `phoneConsent` (Viber/SMS) — отдельные, хранятся и передаются раздельно.
- Передавать в CRM только при регистрации (когда есть подтверждённая почта) и **только при согласии**; хранить время и источник согласия.
- Рассылка: поздравление в день рождения (по дню и месяцу рождения), опционально напоминание за N дней со ссылкой на вишлист и бонусом.

- **Юридическое:** сбор даты рождения и рассылки требуют политики конфиденциальности и обработки персональных данных (с учётом законодательства РБ/ЕС, если применимо). В прототипе чекбокс есть, ссылки на политику нет — добавить до публичного запуска. Права пользователя: просмотр данных (есть блок в профиле), удаление (есть локально, на сервере — реализовать).

## 12. Бонус и UTM

- **Бонус 🔜:** в прототипе — только баннер с текстом-заглушкой (`BONUS` в `src/lib/config.ts`). Условия, размер, срок и механика начисления (UTM-метка, промокод, привязка к аккаунту) определяются бизнесом.
- **UTM ✅ — автоматически во всех ссылках из приложения на surprise.by.** Реализовано единой функцией `withUtm` (`src/lib/utm.ts`); любая новая исходящая ссылка обязана строиться через неё. Существующие параметры ссылки сохраняются. Ссылки открываются с `rel="noopener"` в новой вкладке.

| Параметр | Значение | Смысл |
|---|---|---|
| `utm_source` | `wishlist_app` | источник — приложение |
| `utm_medium` | `app` · `pwa` · `telegram` · `share` · (🔜 `push`) | канал: браузер / установленное на экран / Telegram Mini App / переход по чужой шеринг-ссылке / пуш |
| `utm_campaign` | `card` · `wishlist` · `share` · `about` | откуда внутри приложения: карточка из ленты, из вишлиста, из чужой ссылки, экран «О приложении» |
| `utm_content` | id впечатления (услуги) | какую услугу смотрел человек |
| `utm_term` | id пользователя | анонимный id устройства/пользователя (см. ниже) |
| `ref` | id пользователя-отправителя | только при переходе из чужой шеринг-ссылки — для атрибуции рефералов |

Пример: `https://surprise.by/catalog/katanie_na_baggi/?utm_source=wishlist_app&utm_medium=share&utm_campaign=share&utm_content=152897&utm_term=ufriend000001&ref=uf59042e31ee`

**Идентификатор пользователя** (`src/lib/uid.ts`): случайная строка вида `u<11 символов>`, создаётся при первом запуске и хранится в `wl.uid`. Это **не персональные данные** (не связан с именем, почтой, телефоном). Удаляется вместе с остальными данными по кнопке «Удалить мои данные». 🔜 После регистрации заменяется ID аккаунта (прежний сохраняется для склейки истории). Отнесён к `utm_term` намеренно: Google Analytics и Яндекс.Метрика автоматически сохраняют `utm_*`, и ID доступен в отчётах без доработок сайта; сайт при желании читает `ref` и `utm_term` из URL и сохраняет в заказе.
**Что нужно от сайта:** сохранять `utm_*` и `ref` при оформлении заказа (в заказе/CRM), чтобы начислять бонус и считать конверсию по пользователям и рефералам.

**Требования к бронированию и «Сюрпризу» (для разработки 🔜):**
- Вишлист хранится на сервере и привязан к аккаунту владельца; ссылка шеринга указывает на серверный список (короткая ссылка, §9).
- Получатель ссылки может **забронировать** позицию (нужна минимальная идентификация: имя или вход); у позиции статусы: свободна / забронирована / подарена. Бронь снимается самим забронировавшим.
- Владелец отмечает «желание исполнено»; позиция уходит в раздел «Мне подарили».
- В режиме «Сюрприз» владелец не видит, кто и что забронировал (только общее количество); режим выбирается при создании списка и необратим.
- Уведомления: владельцу — «кто-то забронировал» (без деталей в режиме «Сюрприз»); гостю — напоминание о дне рождения.
- Связь с бонусом: заказ по ссылке из вишлиста учитывается через `utm_term`/`ref` (§12).

## Приложение: история изменений

- **v1** — базовый прототип: свайп-колода, вишлист, карточка, шеринг по URL, UTM, офлайн, синхронизация фида, бренд.
- **v2** — обязательный онбординг (имя, дата рождения), профиль, шеринг отдельного впечатления.
- **v3** — онбординг убран; анкета предлагается после 10-го свайпа; пропущенные карточки возвращаются в конец (настройка в профиле); один фильтр по категории и заглушка ИИ-подбора; окно шеринга упрощено (только ссылка и иконки, добавлен Instagram); добавлены разделы про пуш-уведомления и CRM; публикация на GitHub Pages.
- **v4** — анкета приведена к таблице «4.2 Профиль клиента» (телефон с отдельным согласием, город, сфера деятельности, интересы-теги, год рождения необязателен, возраст считается; «Кому дарите» исключено); возвращены полные фильтры (город, категория, интересы, цена в BYN, возраст, пол, повод) за кнопкой «Фильтры» рядом с быстрым рядом категорий; в синхронизацию добавлены выводимые признаки `interests`, `cities`, `ageGroups`, описано, чего не хватает в фиде.
- **v5** — автоматические UTM-метки во всех исходящих ссылках (источник, канал, кампания, услуга, id пользователя, реферал отправителя); анонимный id пользователя `wl.uid`; параметр `u` в ссылках шеринга; кнопка и окно «О приложении»; вкладка «Колода» переименована в «Впечатления»; добавлен раздел про Telegram-бот (тексты для BotFather, подключение Mini App).
- **v6** — разбор референса wishlist.by (раздел 19) с бэклогом: бронирование, «Сюрприз», видимость списка, шеринг на почту, куки-баннер; реализованы поиск по впечатлениям и быстрый ряд «Повод» (порядок по ближайшему празднику); тексты «О приложении» переписаны с оглядкой на референс: слоган, три шага, частые вопросы; уточнён текст пустого вишлиста.
- **v7** — профиль перенесён из нижнего меню в шапку (аватар справа от «О приложении»), в нижнем меню остались «Впечатления» и «Вишлист»; кнопки «Фильтры» и «ИИ-подбор» стали цветными (зелёная и сиреневая); добавлена подписка на Telegram-канал в «О приложении»; шапка получила «конфетти-полосу» из цветов бренда.
