# ТЗ: «Wish-list» — свайп-приложение впечатлений Surprise.by (прототип)

## 1. Контекст и цель
Маркетинговый веб-апп Surprise.by для тех, кто хочет что-то попробовать, но сам себе не покупает. Человек без регистрации свайпает впечатления как в Tinder: нравится → в вишлист, не нравится → дальше. Вишлистом можно поделиться (друзья, гости на ДР). Переход на сайт идёт по UTM-ссылке, на оформлении через приложение даётся бонус.

**Ценности:** простота, актуальность (фид обновляется ежедневно), лёгкий шеринг, бонус за заказ из приложения.
**Задача этапа:** презентабельный прототип, работающий локально и офлайн. Без регистрации, но архитектура её учитывает.

## 2. Решения брифинга
| Тема | Решение |
|---|---|
| Среда | Локально / офлайн, цель — презентация. Бэкенда нет |
| Стек | Vite + React + TypeScript, PWA (service worker, манифест), mobile-first |
| Хранение | `localStorage` (лайки, дизлайки, фильтры); данные фида — локальный `products.json` |
| Шеринг | Список ID закодирован прямо в URL (без бэкенда) |
| Бонус | Только UTM-метка, сам бонус начисляется вручную на стороне сайта |
| Колода | Стартовый фильтр из 2–3 вопросов → колода по тегам, внутри перемешана |
| Синхронизация фида | Скрипт `npm run sync` + снимок на день презентации в сборке |
| Дизайн | Дизайн-система Surprise из Claude Design: логотипы и цвета применены; шрифт, радиусы и отступы в ней не заданы (§10) |
| Регистрация | Не делаем; предусматриваем точку расширения (§8) |

## 3. Данные: фид `google_merchant.csv`
Источник: `https://surprise.by/google_merchant.csv`. Проверено на выгрузке: **355 позиций**, все `in_stock`.

**Формат (важно):** разделитель `|`, UTF-8, значения в кавычках, первая строка — заголовок. Поля: `id | title | description | product_type | link | image_link | additional_image_link | video_link | price | availability | custom_label_0 | custom_label_1 | custom_label_3`.

**Факты по данным:**
- Фото главное есть у всех; галерея (`additional_image_link`, через запятую) у 347; видео (YouTube) у 46.
- Цена строкой `"105 BYN"`, диапазон 14–1900, медиана 150. Парсить число, валюта всегда BYN.
- `description` ~440 символов в среднем, может содержать «.» подряд и обрезанный текст. Показывать как есть, на карточке обрезать с «ещё».
- `product_type` — 1 строка с десятками тегов через запятую (получатели, поводы, категории). Много шума («Подарки на Новый год 2021…»).
- `custom_label_1` — ценовой диапазон: `до 50`, `50 - 100`, `100 - 300`, `более 300 руб.`; `custom_label_0` — «для нее / для него / корпоративные подарки» (у 130 пустой); `custom_label_3` — вторичный диапазон (не использовать).
- Ссылки `link` без параметров — UTM добавляем сами.

**Нормализация (скрипт sync → `products.json`):**
```
Product {
  id: string
  title: string
  description: string
  url: string            // исходный link
  image: string
  images: string[]       // additional_image_link split(',')
  video?: string
  priceByn: number
  audience: ('her'|'him'|'parents'|'kids'|'couple'|'colleagues')[]
  occasions: string[]    // ДР, 8 марта, 14 февраля, 23 февраля, Новый год, свадьба…
  categories: string[]   // Активный отдых, Спа и красота, Мастер-классы, Полёты, Бары и рестораны, Фотосессии, Квесты…
  priceBucket: 'lt50'|'50-100'|'100-300'|'gt300'
  isGiftCard: boolean    // «Подарочные карты магазинов» / универсальный сертификат
}
```
Маппинг тегов → audience/occasion/category — один справочник в `scripts/taxonomy.ts` (напр. Женщинам/Девушкам/Жене/Сестре → `her`; Мужчинам/Парням/Мужу/Брату → `him`; Родителям/Бабушке и дедушке → `parents`). Неизвестные теги отбрасываются. Подарочные карты/наборы остаются в колоде, но идут в конец (они плохо «свайпаются»).

**Синхронизация:** `npm run sync` скачивает CSV, парсит, валидирует (id уникален, есть image/link/price), пишет `public/data/products.json` + `meta.json` (`syncedAt`, `count`). Ключ `--with-images` дополнительно качает главные фото в `public/img/` для полного офлайна. При падении сети остаётся предыдущий снимок. В проде тот же скрипт по cron раз в сутки. В UI: «Каталог обновлён: дата» в футере вишлиста.

## 4. Пользовательские сценарии и экраны
1. **Welcome (1 экран):** слоган, кнопка «Начать». Без логина.
2. **Стартовый фильтр (2–3 шага, можно пропустить):** «Для кого?» (себе / ей / ему / паре / родителям) → «Бюджет» (по `priceBucket`) → «Повод» (необязательно). Результат — колода; настройки можно сменить из шапки.
3. **Колода (главный экран):** стопка карточек, 1 активная + следующая под ней.
   - Карточка: фото, название, цена, 1–2 тега категории, индикатор галереи.
   - Жесты: вправо/кнопка ♥ → в вишлист; влево/кнопка ✕ → пропуск; тап по карточке → детали; «Отменить» последний свайп.
   - Анимация наклона и метки «Хочу»/«Мимо», клавиатура ←/→ для десктопа.
   - Показанные карточки не повторяются; когда колода кончилась — экран «Вы всё посмотрели», кнопки «Сбросить пропущенные» и «Открыть вишлист».
4. **Карточка впечатления:** галерея (свайп), видео (YouTube-embed по тапу, ленивая загрузка), полное описание, цена, кнопки «В вишлист»/«Убрать», **«Смотреть на surprise.by»** (UTM, новая вкладка), «Поделиться этим».
5. **Вишлист:** сетка/список избранного, сумма «Итого ≈ N BYN», удалить свайпом/кнопкой, кнопка «Поделиться вишлистом», пустое состояние с призывом вернуться в колоду.
6. **Просмотр чужого вишлиста** (`/#/w/<код>`): режим только для чтения, шапка «Вишлист друга», те же карточки, ссылки на сайт с UTM шеринга, кнопка «Собрать свой».
7. **Бонус-блок:** постоянный компактный баннер «Оформляйте через приложение — получите бонус» (текст бонуса — конфиг, §10) в карточке и вишлисте.

Навигация: нижняя панель из 2 вкладок «Колода» / «Вишлист» (с счётчиком).

## 5. Шеринг (URL-кодирование)
- Ссылка: `https://<host>/#/w/<code>[?n=Имя]`. Hash-роутинг — не нужен серверный fallback (работает со статичного хостинга и офлайн).
- `<code>` = отсортированные ID, дельта-кодирование, base36, разделитель `.`; для ~30 позиций это ~120 символов. Версия формата — префикс `1~`, чтобы менять схему в будущем.
- Получатель разворачивает ID по локальному `products.json`; ID, которых нет в текущем фиде, показываются заглушкой «Впечатление больше недоступно», не ломая список.
- Кнопка «Поделиться»: `navigator.share` (мобильные) → fallback «Скопировать ссылку»; готовые кнопки Telegram / WhatsApp / Viber через deep-link с текстом «Мой вишлист впечатлений на Surprise.by».
- OG-превью ссылки в соцсетях в статичном прототипе не делаем (требует сервера); в §9 как следующий этап.

## 6. UTM-метки
К каждому исходящему `url` на surprise.by добавляется (существующие query-параметры сохраняются):
```
utm_source=wishlist_app
utm_medium=app            (из шеринг-режима: share)
utm_campaign=swipe | wishlist | card | share
utm_content=<product id>
```
Единая функция `withUtm(url, campaign, id)`. Значения вынесены в конфиг. Все исходящие клики идут с `rel="noopener"`.

## 7. Нефункциональные требования
- **Mobile-first**, ширина 360–430 px приоритет; на десктопе — центрированная «телефонная» колонка до 480 px.
- **Офлайн:** service worker кэширует оболочку, `products.json` и (при `--with-images`) изображения; без них — графически деградирует до плейсхолдера. Нужен рабочий запуск без сети на презентации.
- **Производительность:** первый экран < 2 c на 4G; предзагрузка 3 следующих изображений колоды; `loading="lazy"` в вишлисте; изображения `webp/png` как есть.
- **Состояние:** `localStorage` ключи `wl.liked`, `wl.passed`, `wl.filters`, `wl.syncedAt`; безопасно при недоступном storage (try/catch, in-memory fallback).
- **Доступность:** кнопки ♥/✕ дублируют жесты, видимый фокус, контраст по гайдлайну, `prefers-reduced-motion`.
- **Язык:** русский, строки в одном словаре (`i18n/ru.ts`) на случай BY/EN.
- **Аналитика (заглушка):** слой событий `track(name, payload)`, пока в консоль: `swipe_like`, `swipe_pass`, `open_card`, `outbound_click`, `share`, `filter_set`. Подключение GA/Метрики позже.

## 8. Заложить на будущее (не делаем сейчас)

## 14. Дополнение v2: обязательный профиль и шеринг (реализовано)

**Обязательный онбординг.** При первом запуске: приветствие → имя и дата рождения (оба обязательны, валидация) → фильтры подборки. Без профиля колода недоступна. Исключение: ссылки на чужой вишлист/впечатление (`#/w/…`, `#/i/…`) открываются без онбординга, чтобы не терять получателей; кнопка «Собрать свой вишлист» ведёт в онбординг.

**Профиль** (`localStorage: wl.profile`, версия схемы `v:1`, `src/lib/profile.ts`):

| Поле | Статус | Примечание |
|---|---|---|
| `name`, `birthDate` | обязательно, при входе | |
| `email` | по желанию, в профиле | база для CRM; обязательна при регистрации |
| `gender` (f/m/o), `position`, `interests[]` | по желанию | интересы = категории каталога |
| `age` | не хранится | считается из `birthDate` (`exportProfile`) |
| `marketingConsent` | чекбокс, по умолчанию выключен | основание для CRM-рассылок |

Вкладка «Профиль»: аватар-инициал в цветах бренда, возраст, форма редактирования, блок «Какие данные хранятся» (JSON, который уйдёт в БД), «Удалить мои данные». Напоминание за 30 дней до ДР предлагает отправить вишлист гостям.

**Миграция в БД при регистрации:** объект `wl.profile` → таблица профилей 1:1; `email` и пароль добавляются в форме регистрации, имя и дата подтягиваются автоматически.

**Шеринг (приоритет №2):** (а) весь вишлист `#/w/<код>?n=Имя`, (б) отдельное впечатление `#/i/<id>?n=Имя` — кнопка «Поделиться этим впечатлением» в карточке. Имя отправителя подставляется из профиля. Каналы: системное меню, копирование, Telegram, WhatsApp, Viber. События аналитики `share` содержат `kind` и `via`.

**Риски/решения для согласования:** сбор даты рождения и рассылки требуют политики конфиденциальности и согласия — сейчас есть чекбокс, но нет ссылки на политику; серверной доставки данных в CRM пока нет (данные только на устройстве).
